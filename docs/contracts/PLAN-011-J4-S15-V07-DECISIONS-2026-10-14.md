# PLAN-011 — J4·S15·V07 승인 정책과 남은 기술 항목

> 2026-10-14 최신 사용자 승인: [단순화 결정](PLAN-011-SIMPLIFICATION-DECISION-2026-10-14.md). 재가입 유료 우선·원 소비당 target 복원1회 유지, 생성 중 삭제 미접수·앱 MEMBER 보강·120일 멱등 보장/종료 상세 기록 정리 채택. 이후 과거 key 신규 처리 위험 수용, 금융/소비/미완료 증거 보존은 유지. 아래 대기열 삭제/영구 key 보장 전제는 이 범위에서 대체하며 구현·공동 exact는 후속이다.

> 후속 기술 제안: [네 항목 권장안 R1](PLAN-011-REMAINING-TECHNICAL-PROPOSAL-R1.md). 기존 purchase-account 증거·삭제 전달/경합·phone paid-first·자료별 보존기간 후보를 공동 검토한다. 추가 정책/기간/route가 최종 승인된 것은 아니다.

- 날짜: 2026-10-14
- 상태: 사용자 승인 정책 통합. 공동 exact 계약·새 fixture·제품 구현·배포 완료 아님.
- 관련: PLAN-011/012/013, TMI-116/TMI-128/TMI-122, TMI-125.
- 근거: J4 「1번으로 해줘」, S15 사용자 삭제 「2번으로 해도 될 거 같은데」, V07 「권장으로 하면 될 거 같은데」 및 문서 동기화 요청.

## 1. 5줄 결론

1. J4는 Identity 검증 MEMBER 증거 보존과 기존 탈퇴 이벤트/복구를 사용하며 일부 전파 지연을 허용한다.
2. S15 사용자 시험 삭제는 해당 시험의 재응시 포기로 처리하고, 삭제를 이유로 사용한 무료권을 복원하지 않는다.
3. 삭제 뒤 의도적 새 시험은 새로운 권리 판정으로 시작한다. 유료 기간·다른 무료권·이미 지급한 복원권은 보존한다.
4. V07은 진행 중 복구 증거를 유지하고 종료 후 최소 증거만 목적별 정해진 기간 보존한다. 기간 숫자와 폐기 조건은 미확정이다.
5. phone 재가입 선택·MEMBER 최초 증거 전달·삭제 경합/중복 차단·보존 상세가 남았으며 LC/Identity 공동 확인 후 구현한다.

## 2. 사용자가 반드시 읽어야 하는 내용

### 2.1 확정 정책

| 항목 | 확정 내용 | 확정하지 않은 것 |
| --- | --- | --- |
| J4 | MEMBER→GUEST 없음, 탈퇴 외 계정 상태 없음 전제. MEMBER 검증 증거 보존·기존 탈퇴 연동·지연 허용 | 증거 최초 수신/보강 exact·운영 지연 기준·무제한 지연 허용 |
| S15 사용자 삭제 | 삭제한 시험을 이어풀거나 원 consumption으로 재응시하지 않음. 사용 무료권 미복원 | 사용자 삭제가 아닌 중도 이탈/시스템 cleanup까지 동일 취급 |
| 삭제 후 새 시험 | 새 key/새 시험·INITIAL·새 권리 판정. 유효 paid 또는 남은 무료권 사용, 없으면 기존 권리 부족 처리 | 삭제만으로 새 무료권 지급·새 Claim 개방 |
| 보존하는 권리 | 유료 잔여기간·다른 무료권·이미 지급된 복원권 유지 | 삭제 시 다른 권리 회수·금융 성공 사실 삭제 |
| V07 | 진행 중 복구 증거 유지, 종료 후 목적에 필요한 최소 증거와 정해진 보존기간 | 모든 자료에7일/120일/5년 일괄 적용·무기한 개인정보 보존 |

삭제는 사용자의 명시적 시험/학습자료 삭제 의사가 확인된 경우다. Session 문서가 없다는 이유만으로 사용자 삭제를 추정하지 않는다. 시험 중 나가기·앱 종료·응답 유실·시스템 TTL과 구분한다. 기존 중도 이탈의 같은 문제 재시작 정책은 유지한다.

사용자 삭제 이후에는 기존 삭제/lifecycle deny가 우선한다. 기접수 작업 완료 허용 정책으로 삭제된 답안·결과·Summary를 되살리지 않는다. 소비/복원 중복 방지의 Billing 최소 증거는 학습자료와 분리한다.

앱 삭제 안내 문구 제안: “이 시험의 기록과 재응시 기회가 사라지며, 사용한 무료권은 돌아오지 않습니다.” 실제 UI 변경은 수행하지 않았다.

### 2.2 J4 정리

[상세 결정](PLAN-011-J4-MEMBER-EVIDENCE-DECISION-2026-10-14.md)을 따른다. MEMBER 증거와 탈퇴 deny를 분리하며 늦은 MEMBER 증거로 탈퇴를 되돌리지 않는다. 사용자 토큰 없는 worker도 정규화된 증거로 처리한다. 증거 부재는 GUEST 판정/무료 우회가 아니다. 매 시험 동기 조회와 새로운 전체 회원상태 동기화 시스템을 기본안에 넣지 않는다.

## 3. 남은 공동 기술 항목

| ID | 담당 | 구체화할 것 |
| --- | --- | --- |
| M1 | Identity/Billing | MEMBER 최초 증거 출처·검증·user/environment 결속·기존 계정 보강·증거 없을 때 복구 |
| D1 | LC/Billing | 명시 삭제 사실을 Billing이 신뢰할 수 있게 전달하는 방법·삭제 event와 신규 reserve 순서·중복·지연·응답 유실 |
| D2 | LC/Billing | 삭제와 reserve/confirm/LC 마무리 경합. 삭제 선행 시 복원 자격/원 재응시 차단, confirm 선행의 이미 지급된 복원권 보존 |
| D3 | LC/Billing | 같은 key 과거 성공 replay가 삭제 Session을 재생성하지 않게 하고, 삭제 후 새 key INITIAL을 허용하는 exact 요청/응답 |
| P1 | LC/Billing | phone continuation과 유효 paid 동시 존재 시 권리 선택·startReason. 삭제 정책과 별개로 공동 확정 |
| R1 | Billing/LC | receipt/group 최초 사실/terminal tombstone/legacy 목록 각각 보존기간·폐기 조건·폐기 후 조회/재유입 처리 |

D1~D3는 새 복구 시스템을 만들라는 뜻이 아니다. 기존 삭제/lifecycle 경로와 operation fence를 우선 사용한다. 다만 기존 R2에서 Billing-linked 대상의 restartContext 누락을 conflict로 처리하므로, 삭제 후 무조건 context를 생략하는 구현은 허용하지 않는다. 삭제 사실 전달 방식과 INITIAL의 안전한 판정을 새 보완 계약에서 함께 정한다. 이번 문서에서 새 route/event/schema를 발명하지 않는다.

Billing에 삭제가 반영되기 전 경합의 허용 범위는 J4 탈퇴 지연 허용과 별개의 기술 확인이다. “사용자가 삭제했으므로 후속 처리를 고려하지 않는다”는 뜻으로 확대하지 않는다. 삭제된 원 시험을 사용한 복원 지급은 금지하는 정책을 원자 경합 순서로 구현해야 한다. 이미 먼저 확정된 지급은 삭제 때문에 회수하지 않는다.

phone은 별도다. 유료 우선은 이전 권장안이지 이번 삭제 선택으로 공동 exact까지 확정된 것은 아니다. 정상 지원을 미확정 상태로 fixture 성공 처리하지 않는다.

## 4. 주요 위험과 미확인 사항

- LC에서만 문서를 지우고 Billing group을 계속 재응시 가능 상태로 두면 포기 정책이 적용되지 않는다. D1/D2가 활성화 선행 조건이다.
- 문서 부재를 삭제로 추정하면 장애/이관 누락으로 사용자의 권리를 잃게 할 수 있다. 명시 사실과 exact 원 대상을 검증한다.
- 삭제 후 과거 요청 replay와 의도적 신규 요청은 다르다. 과거 성공은 금융 증거로 보존하지만 삭제된 학습자료를 복구하지 않는다.
- 증거를 일찍 지우면 늦은 중복 지급·revoke 충돌을 놓친다. 무기한 보관으로 해결하지 말고 보존 종료 후 동작까지 정한다.

정확 기간은 아직 승인하지 않았다. 7일 command/120일 inbox 수치가 다른 복구 증거의 폐기 근거가 되지 않는다. 진행 중 보존은 영구 유지 약속이 아니라 복구/종료를 완료할 의무와 함께 적용한다.

## 6. 부록 — 문서·fixture 반영 범위

[PLAN-011](../plans/PLAN-011-paid-reservation-and-usage-evidence.md), [저장 설계](../plans/PLAN-011-STORAGE-TRANSACTION-DESIGN-R1.md), [공동 합의안](LC-BILLING-PAID-EXAM-R2-IMPLEMENTATION-AGREEMENT-R1.md), [J3/J4 보완안](LC-BILLING-PAID-EXAM-J3-J4-ADDENDUM-R1.md)의 삭제 continuation 복구 제안은 **명시적 사용자 삭제** 범위에서 이 정책으로 대체한다. 기존 재응시 증거 claim/transfer로 삭제 시험의 무료 재응시를 복구하는 기능은 이 범위에서 제외한다. 시스템 삭제·phone·비삭제 owner 이전을 일괄 폐기하는 승인은 아니다.

R2 draft-2/fixtures-2는 당시 검증 원본으로 보존한다. 원문 hash를 유지한다고 최신 삭제 정책까지 기존 fixture로 검증됐다는 뜻은 아니다. D1~D3 exact 확정 후 별도 contract/fixture revision에 사용자 삭제→재응시 차단·신규INITIAL·무료권 미복원·다른권리 보존·경합·지연삭제를 추가하고 양측 검증한다. J3의 이미 해소된 의견은 다시 열지 않는다.

LC 전달: 이 통합 결정을 공유하고 D1~D3/P1/R1의 기술안 확인을 요청한다. Identity 전달: M1의 최초 MEMBER 증거 계약을 확인한다. 이번 작업에서는 외부 메시지를 보내지 않았다.

문서 링크·diff·기존 원본 hash 검증만 수행한다. 제품 코드·schema/DB·LC/Identity 저장소·Jira·배포·commit/push 변경 없음. 문서 작업이므로 Gradle 재실행 없음.
