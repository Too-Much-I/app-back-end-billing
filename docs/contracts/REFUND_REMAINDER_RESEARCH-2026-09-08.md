## 1. 5줄 결론

1. 전자상거래법은 제공이 시작된 콘텐츠의 제한과 가분적 미제공 부분의 예외를 구분한다. 하루 이용했다는 사실만으로 남은 27일 환불을 일괄 거절할 수 있다고 단정할 수 없다.[S1]
2. 토선생의 법적 분류와 공제식은 아직 확정할 수 없다. '잔여기간 비례 반환·추가 위약금 없음'은 권장 운영안이지 모든 사안에 법이 강제하는 단일 공식이 아니다.[S1][S2]
3. Google Play Console은 인앱 상품 부분 환불을 지원한다. Apple도 consumable에 사용률을 첨부해 비례 환불을 권고할 수 있지만 최종 결정은 Apple이다.[S3][S5]
4. RevenueCat Refund Control은 현재 부분 환불 선호·거래별 사용률 전송을 지원하지 않는다. Google 접근 철회 없는 환불의 미탐지 안내도 있어 Store 지원과 Billing 자동 반영을 동일시하면 안 된다.[S8][S9]
5. 현재 ADR-004는 부분 환불 금액·누적 환불·해지 효력 시점을 충분히 정의하지 않았다. 출시 전 법적 분류 확인과 실행 경로 검증 후 별도 승인으로 계약을 보완해야 한다.[L1]

분석상 출발점은 '성인 대상 기간형 온라인 AI 모의고사·채점 서비스'다. 파일 한 개 판매나 강사 수업형 수강계약보다는 기간 동안 신규 시험·채점 기능을 이용하는 권리로 설명하는 것이 실제 제공 형태에 가깝다. 다만 IT 업종/교육시설 미등록 사실만으로 교육 관련 법령 적용 제외를 확정하지 않는다. 가분성·계속거래·구체 환급 기준은 별도 검토 대상이다.

상담에는 '기간 중 신규 시험·채점 무제한 이용'과 '이미 생성된 결과 열람'을 분리해 설명한다. 결과 열람 잠정안은 계정 탈퇴 뒤 보존·접근이나 기존 승인된 COMPLETED history 보존 계약을 변경하는 승인이 아니다. 파일 다운로드가 없다고 이미 제공한 결과의 가치가 없거나 전액 환불이 항상 의무라는 의미도 아니다.

추가 자료는 할인 여부·세금 구성, 구매 화면/약관·동의 초안, 환불 접수/효력 시점, 서비스 장애 처리다. 아래 28,000원 계산은 가상 예시이며 실제 제시된 4주권 가격은 69,000원이다. 사용자의 이번 사실 확인을 일할 환불·부분 환불 구현 승인으로 간주하지 않는다.

환불 창구에 대한 사용자 질문에는 Store를 기본 접수/환급 경로로 두고 앱에는 안내 링크와 고객지원 연락 수단을 제공하는 방향을 제안한다. Billing 자체 환불 신청 API나 앱 내 자체 심사 UI가 반드시 필요한 것은 아니다. 단, Store 환불은 항상 승인되는 것이 아니며 장애·미제공·법령상 요청의 개발자 대응을 전부 제외할 수 없다. 고객지원은 이메일 등으로도 구성할 수 있고 법적 환급의무가 발생할 때 실제 실행 가능한 경로와 기한을 검증해야 한다. 이는 외부 송금 또는 부분 환불 실행 승인이나 출시 gate 해제를 뜻하지 않는다. 검증된 Store 환불 결과의 원장·권리 반영은 별도로 필요하며 앱의 '환불 신청했다'는 주장만으로 완료 처리하지 않는다.

### 2.1 반환 의무는 있는가

확인된 법령은 전자상거래법 제17조·제18조다. 제17조 제1항의 일반 청약철회 기간은 법정 기산점부터 7일이며, 제2항 제5호는 제공이 개시된 용역/디지털콘텐츠의 제한을 정하면서 가분적 계약의 미개시 부분을 예외로 둔다. 제6항의 표시·시험 사용 등 조치도 확인해야 한다. 하자·표시광고/계약과 다른 이행에는 제3항의 별도 기간이 있다.[S1]

따라서 '4주권을 하루 이용했으므로 전체 공급 완료'라고 정하기는 어렵다. Store의 consumable 또는 SDK completion은 결제 상품 처리 방식이지 한국법상 28일 서비스 전체 제공 완료의 증거가 아니다. 다만 토선생의 약관·실제 제공 방식 없이 가분성, 인터넷콘텐츠/교육서비스 해당 여부, 계속거래 적용 여부와 정확한 반환액을 확정할 수는 없다. 이는 조사상 미확정이지 반환 의무가 없다는 결론이 아니다.

청약철회와 일반 중도해지는 별도다. 전자상거래법상 제17조 제1항 철회에는 제18조 제9항상 위약금·손해배상 청구 제한이 있다. 제18조 제8항의 일부 이용 이익/비용 청구도 대통령령 범위 안에서만 가능하므로 임의의 AI 비용이나 판매 수수료를 공제식에 더하지 않는다. 해당 대통령령 항목의 토선생 적용은 이번 조사에서 확정하지 않았다.[S1]

### 2.2 계산은 어떻게 하는가

검토를 권장하는 단순 운영안은 다음과 같다. 아직 승인된 정책이나 확정된 법정 계산식이 아니다.

```text
잔여기간 반환액 = 실제 결제금액 × 반환 대상 미제공 기간 ÷ 총 계약기간
추가 위약금 = 0
```

가상 가격 28,000원에 672시간을 구매하고 정확히 24시간이 제공된 뒤 나머지 기간을 종료한다고 가정하면, 28,000 × 648 / 672 = 27,000원이다. 단순변심의 이 예시를 장애·미제공·계약 불이행·전액 철회 사안에 일괄 적용하지 않는다. 법령이 더 유리한 반환을 요구하거나 Store가 전액 환불하면 해당 결과를 우선한다.

기간형 unlimited에서 '이용'은 실제 앱 접속 시간이나 시험 횟수가 아니라 정상적으로 서비스가 제공된 계약기간을 기준으로 보는 운영 제안이다. 정당한 환불 접수 뒤 담당자 처리가 늦은 날까지 사용기간으로 공제하지 않도록 접수·법적 효력·접근 종료·환급 완료 시점을 따로 정해야 한다. 아직 시작하지 않은 scheduled slot, 서비스 장애, 할인, 세금, 통화별 반올림도 별도 기준이 필요하다.

문화체육관광부 콘텐츠이용자 보호지침 제25조는 특정 스트리밍 계속적 콘텐츠의 이용자 사유 해지에 사용분과 잔여대금 10% 이내 손해배상 공제 기준을 제시한다. 그러나 제3장 권고사항이고 적용 대상·사유에 조건이 있다. 모든 앱의 모든 환불에 총 구매금액 10%를 공제하는 법정 공식이 아니다. 이번 권장안은 이 공제를 자동 채택하지 않는다.[S2]

### 2.4 Billing에는 어떻게 반영해야 하는가

현재 결제 application code는 미구현이다. [ADR-004 §5.7·§5.9][L1]의 설계는 최종 환불에 Purchase terminal 전이·권리 revoke·reversal·timeline 재배치·접근 차단을 연결하지만, 부분 금액과 누적 환불은 구체화하지 않았다.

부분 반환을 지원하려면 돈과 권리를 분리해야 한다.

- 예시 금전 기록: 구매 28,000원 원본 유지 → 실제 확정 환불 27,000원 별도 추가 → 누적 환불 27,000원/미환불 1,000원.
- 권리 기록: 잔여기간 해지에 따른 환불이면 해당 이용권의 앞으로의 사용은 종료한다. 금액의 일부만 돌려준다는 이유로 남은 권리도 일부 살리는 것은 아니다.
- 과거 완료 시험·무료권은 그대로 보존한다. 선행 GRADING 처리 등 승인된 보호 조건도 보존한다.
- '일부 금액만 할인 보상하고 사용은 계속'은 잔여기간 해지와 다른 정책이며 이번 범위에서 채택하지 않는다.

Store가 실제 28,000원을 돌려줬다면 우리가 제안한 27,000원이 아니라 28,000원을 원장에 기록한다. 예상 계산, 환불 요청, provider 접수, 최종 환급을 혼동하지 않는다. 신뢰할 수 있는 최종 증거가 없을 때 완료로 꾸미지 않으며, 증거 조회 지연도 정상 무환불로 숨기지 않는다.

## 3. 사용자가 결정해야 하는 사항

순서는 법적/사업자 지원 확인 → 운영 선택 → ADR·PLAN 보완 승인이다. 이번 조사로 자동 확정한 내용은 없다.

1. 국내 상품 분류와 기준 검토: 실제 결제 화면·28일 제공 방식·약관·stacking·사업 형태를 가지고 변호사 단건 검토 또는 콘텐츠 관련 분쟁조정/사업자 상담을 받는다. '가분적 서비스인지, 청약철회/일반 해지별 반환과 공제 기준, 적용 기산점'을 질문한다.
2. 운영안: 법정 권리를 하한으로, 잔여기간 비례 반환·추가 위약금 없는 정책을 채택할지 확인한다. 실제 가격·세금·할인·반올림·장애 시간을 포함한 exact 계산은 그다음 확정한다.
3. 실행 경로: RC에 Apple consumable GRANT_PRORATED/사용률 전달, Google consumed one-time 부분 환불의 webhook/API 금액·고유 refund 식별자·철회 상태 지원을 확인한다. 지원이 부족하면 별도 승인된 운영 증빙 수집·Store adapter 경로가 필요하다.
4. 범위 변경: 부분 환불 금액 원장·접수/효력 시점·운영 권한을 최초 출시 범위에 추가할지 승인받는다. 단순히 '부분 환불 미구현'으로 법정 요청을 거절하는 방안은 선택지로 두지 않는다.

## 4. 주요 위험과 미확인 사항

- 28일이 언제나 법령상 '1개월 이상' 계속거래이거나 언제나 제외된다고 단정하지 않는다. 월 단위 기간 계산·연속 구매 연결·약관 구조를 함께 검토해야 한다. 기간을 28일로 정했다고 반환 의무가 사라지지 않는다.[S2]
- 토선생이 교육 관련 별도 규제 대상인지, 실제 계약 상대/대금 수령 구조·판매 국가별 의무는 공개 기술 문서만으로 미확정이다. 법무팀 부재가 검토 생략 사유는 아니다.
- 전자상거래법 제18조는 디지털콘텐츠/용역의 적법한 철회에 3영업일 환급 및 결제 취소 요청 관련 의무를 둔다. 내부 첫 응답 목표나 Apple 심사 시간, RC 24시간 탐지는 법정 기한을 대체하지 않는다. 적용 기산점·주체는 계약 구조와 함께 확인한다.[S1]
- Google 일부 결제수단 제한, Apple 최종 결정, RC 부분 금액/중복 이벤트 의미 때문에 고객에게 동일한 자동 처리 결과를 약속할 근거가 부족하다.
- 별도 계좌 반환은 중복 환불·개인정보·세무·Store 약정 문제가 있다. 지침의 대체 반환 안내만으로 외부 송금 경로를 자동 승인하지 않는다. 전액 환불로 더 유리하게 해결하는 운영도 실제 실행 가능 여부를 먼저 확인한다.
- 서비스 접근 종료와 돈의 환급 완료는 시점이 다를 수 있다. 유효한 해지 접수를 처리하는 내부 명령과 검증되지 않은 앱의 환불 주장도 구분해야 한다.
- 실제 RC project, Store sandbox/한국 결제수단, 고객 주문, 부분 환불 event fixture는 확인하지 않았다. 공개 문서의 기능 존재만 검증했다.

## 5. 현재 작업과 직접 관련된 보완 범위 — 제안, 미승인

ADR-004를 바로 바꾸지 않고 다음 계약을 후속 승인 대상으로 식별한다.

- 별도 환불 operation: purchase 연결, 검증 근거/정규화 reference, 사유, 통화, 실제 refund amount, 누적 금액, request/effective/settled 시점, processing/financial status, entitlement action. 민감 원문은 저장하지 않는다.
- 멱등성: 구매 하나에 여러 정당한 부분 환불 가능. 구매 ID 하나 또는 REFUND type 하나로 모두 중복 처리하지 않는다. provider refund ID와 증거 보강 규칙, 최대 구매금액 cap, 부분 후 전액의 미환급 차액 반영을 정한다.
- 금전과 권리 ledger: 원 구매 보존·확정 금액 delta append. 권리 종료와 관련 예약/그룹 차단·durable outbox·후속 미시작 timeline reflow는 승인된 Transaction/CAS 불변식을 따른다. 같은 해지/환불의 이중 reflow·무료 복원 금지.
- 접수/종료: 담당자 지연으로 반환액이 감소하지 않는 효력 시점, 이용자 철회 가능 여부, 실패/거절/추가 환불/환불 취소 상태와 접근 정책을 명시한다. 현행 provider-final 차단 외 새 법적 해지 명령은 인증·권한·감사·외부 계약 영향이 있어 별도 승인한다.
- 증거 경로: RC로 전달되지 않는 부분 환불은 reconciliation만 반복해 해결된다고 주장하지 않는다. 공식 지원 또는 별도 승인된 Store 증거 adapter/운영 절차가 필요하다. 미확인 상태는 검토·경보 대상이며 무기한 대기를 정상 결과로 숨기지 않는다.
- 회귀 테스트: 부분→추가 부분→전액, 중복/역순/응답 유실, 금액 초과/통화 불일치/세금/반올림, 부분 환불과 access revoke의 독립 상태, request/settlement 시간 차이, refund-reserve-confirm 경합, LC GRADING/COMPLETED 보호, 무료권 불변, reflow 중복 방지, 환불 취소 수동 검토.

## 6. 부록 — 공식 근거와 계산 조건

### 6.1 법률과 지침의 구분

| 근거 | 확인된 내용 | 제한 |
| --- | --- | --- |
| 전자상거래법 제17조 | 7일 철회 원칙, 개시된 공급 제한/가분적 미개시 부분 예외, 고지·시험 사용 등 | 토선생의 분류·구체 공제식 자동 확정 아님 |
| 전자상거래법 제18조 | 디지털/용역 환급 기한, 사용 이익/비용 범위, 제17조 제1항 철회의 위약금 제한 | 임의 AI 원가·수수료 공제 근거 아님 |
| 콘텐츠이용자 보호지침 제1조 | 사업자 자율 준수 유도 | 지침 전체를 강행법과 동일시하지 않음 |
| 동 지침 제2조 제7호 | 1개월 이상 계속 공급하며 중도해지 환급 제한/위약금 약정이 있는 계속거래 정의 | 28일/stacking은 실제 구조 검토 필요 |
| 동 지침 제11·12·16·17조 | 철회와 해지 효과, 과도한 위약금/부당한 잔액 반환 거부 방지, 환급 절차 | 일반 철회와 일반 해지를 동일시하지 않음 |
| 동 지침 제3장 권고사항 제25조 | 조건에 맞는 스트리밍 계속적 콘텐츠: 사용분과 잔여대금 10% 이내 공제; 사업자 귀책은 별도 손해배상 방향 | 모든 환불의 총액 10% 공제 규칙 아님 |

제25조의 이용자 임의 해지는 사업자가 동의했거나 계속거래인 경우라는 조건이 있다. 제25조 제3항에는 기간별 할인율이 다를 때 이용 기간에 맞는 더 짧은 기간 할인율 적용 조건도 있어 단순 일할 계산과 항상 같지 않다. 가상 28,000원/하루 1,000원 예에서 잔여 27,000원의 10%는 2,700원이고 공제 시 24,300원이지만, 이는 해당 기준 적용을 가정한 산술일 뿐 토선생의 승인 정책이나 법정 환불액이 아니다. 본문 제안은 추가 위약금 0이다.

### 6.2 Apple 새 API와 RevenueCat 차이

Apple `refundPreference`는 App Store Server API 1.19+에서 DECLINE/GRANT_FULL/GRANT_PRORATED를 제공한다. consumable·non-consumable·non-renewing에는 consumptionPercentage를 포함할 수 있다. auto-renewable은 이 필드를 넣지 않고 Apple이 자동 계산한다. ConsumptionRequest의 사용률 단위는 milliunits 정수 0~100000이다. 이는 데이터 형식이지 토선생의 법적 사용률 계산법은 아니다.[S5][S7]

RevenueCat은 같은 Apple 기능을 모두 노출하지 않는다. RC 문서는 거래별 사용률·usage event 미수집/미전송, Partial refund preference 미지원이라고 명시한다. 따라서 'Apple 부분 환불 불가능'도 틀리고 'RevenueCat 사용 중이므로 27/28 자동 환불 가능'도 근거가 없다.[S8]
