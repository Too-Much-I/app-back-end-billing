## 1. 5줄 결론

1. 앱 문의의 환불(REFUND) 분류로 상담을 접수하고 2영업일 이내 1차 답변한다.
2. Google은 팀 검토 후 지원되는 Store 환불을 실행하고, Apple은 고객 신청을 안내한 뒤 Apple 최종 심사를 따른다.
3. 부분 환불 확정에도 해당 구매의 남은 이용권은 종료하며 다른 구매와 무료권은 보존한다.
4. 문의·팀 검토는 실제 환불 확정이 아니다. 검증된 결과의 Billing 반영 및 상태별 접근 차단이 필요하다.
5. 프론트가 최종 문구를 작성하되 실제 운영·법적 고지·부분 환불 원장 검증 전 이 초안을 게시하지 않는다.

## 4. 주요 위험과 미확인 사항

- Store는 항상 환불을 승인하지 않는다. 스토어 재량 환불 거절을 별도 법적 요청 거절로 자동 변환하지 않는다.
- Google Console 부분 환불 지원과 RC 금액/상태 자동 수신은 별개다. Apple 비례 환불 권고는 최종 승인·지정 금액 환급을 보장하지 않는다.
- 현재 범위의 부분 환불 미구현으로 법정 반환을 거절할 수는 없다. 적용 의무가 있다면 실제 처리 가능한 운영/기술 경로를 별도 승인하고 검증한 후 판매한다.
- 이메일 첫 응답 목표, Store 심사 시간, RC 수신 지연은 법정 처리 기한을 대체하지 않는다. 고객지원 경로만 마련했다고 이 조건이 해결되지는 않는다.
- 승인된 RC 자동 refund handling OFF 유지. 사용률/개인정보를 실제 동의와 adapter 지원 확인 없이 전달하지 않는다.

## 5. 현재 작업과 직접 관련된 설명

이번 변경은 운영 계약과 문서 초안이다. 기존 public payment 4 route와 internal SigV4·사용자 JWT·무료권·owner lifecycle·ledger 불변식은 유지한다. 앱/이메일 주장만으로 지급·환불·owner를 변경하지 않는다.

Billing은 신뢰할 수 있는 최종 Store 결과를 RevenueCat 경로로 검증하고 기존 refund Transaction·append-only reversal·LC durable revoke로 수렴한다. 부분 금액처럼 기존 계약으로 충분히 판정할 수 없는 케이스는 지원·증거·원장 계약 검증이 선행되어야 하며 일반 전액 REFUNDED로 오인하지 않는다.
