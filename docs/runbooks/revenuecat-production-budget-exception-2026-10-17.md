# RevenueCat 운영 준비 — 저빈도 테스트 호출량 분리 예외

> 2026-10-19 사용자 결정: 테스트·운영 프로젝트 통합 budget 신규 개발은 현재 후속 작업에서 제외한다. 기존 서버별 호출 제한·429/Retry-After/backoff는 유지한다. 테스트 트래픽 증가 또는 반복적인 결제 반영 지연 시 재검토한다. 아래 키·운영 준비 미완료 표현은 10/17 당시 기록이며 현재 활성화 상태는 CURRENT_STATE.md를 따른다.

## 1. 5줄 결론

1. 사용자는 기존 RevenueCat 프로젝트·앱을 운영에서도 사용한다.
2. 테스트 결제가 드물다는 전제로 테스트·운영 클러스터의 budget을 분리하는 초기 운영 위험을 수용했다.
3. 이번 범위에서는 기존 문서의 프로젝트 전체 단일 budget DB 요구를 예외 처리하고 공유 연결 신규 개발을 미룬다.
4. 각 환경의 기존 호출량·동시성 제한과 429/Retry-After/backoff 처리는 유지한다. 무제한 호출이나 검증 우회는 승인되지 않았다.
5. 운영 budget DB·최소권한·서버키·상품 매핑 준비와 기능 활성화는 아직 완료되지 않았다.

## 2. 반드시 읽어야 하는 내용

두 클러스터에 같은 DB명을 만들어도 실제로는 별도 budget이다. 따라서 프로젝트 합산 상한·한 환경의 auth/rate block이 다른 환경까지 즉시 전파된다는 보장은 없다. 합산 트래픽이 RevenueCat 제한을 넘으면 429와 결제 반영 지연이 발생할 수 있다. 서버는 미확인을 실패/미구매로 확정하지 않고 기존 대기·재시도를 따른다.

## 3. 사용자 결정

2026-10-17 사용자: “어차피 테스트에서 결제는 많이 안할 거라 상관없어”. 초기 저빈도 테스트 운영에 한정한다. 부하 테스트·테스트 트래픽 증가 전에 테스트 worker 중지/제한 또는 공유 budget 연결을 재검토한다. 운영 전용 키와 webhook 인증값은 테스트와 분리한다.

## 4. 위험·미확인

- 분리 budget은 프로젝트 전체 rate limit을 보장하지 않는다.
- 실제 허용량, 운영 budget 계정권한과 초기화는 별도 점검한다.
- 기존 데이터 삭제·테스트 설정 변경·자동 환불 실행은 포함하지 않는다.

## 5. 현재 작업·검증

RevenueCat 로그인 확인 후 `billing-production-read`, API V2, Purchases Configuration Read only, 나머지 No access로 생성 폼을 준비했다. Generate는 사용자가 직접 수행한다. 아직 키 생성·AWS 저장·RC API 호출·worker 활성화는 하지 않았다. 실제 API 접근 검사에서 추가 권한 필요 여부를 확인하되 임의 write 권한을 추가하지 않는다.
